tokentracker

tokentracker saves the token usage your AI coding tools already record (daily totals per tool and model, on every machine) into a repo on your own GitHub, and publishes it as an API on GitHub Pages. There is no tokentracker account and no tokentracker database.

Your API lives at:

https://<your-github-username>.github.io/tokentracker-data/api/v1/

Quickstart

curl https://bicrick.github.io/tokentracker-data/api/v1/stats.json
const res = await fetch('https://bicrick.github.io/tokentracker-data/api/v1/30d/usage.json');
const { totals, rows } = await res.json();
// rows: [{ period: "2026-10-22", tokens, input, output, reasoning, cacheRead, cacheWrite, responses, split }, ...]

That's real data for bicrick. Swap in your GitHub username once you've installed it.

Install

Needs Node 22.13+ on macOS, Linux or Windows, and a GitHub account. Nothing else.

npx @bicrick/tokentracker init
  1. Finds the AI tools on this computer and shows what it found. You choose which to track.
  2. Asks for your Cursor username, if you use Cursor (optional).
  3. Signs you in to GitHub: open github.com/login/device and enter the code it shows. (If the gh CLI is signed in, it uses that instead.) The sign-in can only touch public repos and workflows, and doesn't expire.
  4. Creates a public tokentracker-data repo on your GitHub, saves your history there and turns on GitHub Pages.
  5. Turns on an hourly background sync (no admin rights).

Setup takes under a minute. Your repo's Action then builds your API in about a minute more. On another computer, run the same command with the same GitHub account; totals add up and the same computer is never counted twice.

With an agent

Ask: Install tokentracker for me. The agent asks whether you use Cursor, runs npx @bicrick/tokentracker@latest init --yes, shows you the GitHub sign-in code (init exits with status 2 while it waits), then runs the same command again to finish. Agents get everything from llms.txt.

API on GitHub Pages

Base: https://<you>.github.io/tokentracker-data/api/v1/. Plain JSON files, public, no key, CORS *. Rebuilt by your repo's Action within about a minute of each sync (hourly), and cached by GitHub for up to 10 minutes.

FileContents
stats.jsonTotals, active days, busiest day, streaks, today, this month, top tool, top model
usage.json · usage-week.json · usage-month.jsonUsage over time by day, week (from Monday) or month, split by tool
models.jsonPer model and tool: tokens, responses, share, first and last used
tools.jsonPer tool
devices.jsonPer computer, with last sync
heatmap.json · heatmap-365d.json · heatmap-90d.jsonReady-to-render calendar grid
profile.jsonSummary and links to everything
rows.jsonEvery daily row, for your own queries
index.jsonList of every file

The same files exist for a time range in a folder: ytd/, 30d/, 90d/, 365d/, e.g. 30d/usage-week.json. Without a folder, files cover all time. Each file's shape is described in Resources below.

Your repo's Pages site is also your profile page, and llms.txt there tells an agent how to read your data: bicrick.github.io/tokentracker-data.

Custom queries

Static files can't take parameters. For any other range, tool or model filter, grouping or CSV, use the query layer. It reads your rows.json from GitHub Pages on each request, computes the answer, and stores nothing:

https://tokentracker.patrickbrown.dev/api/v1/users/<you>/usage?from=2026-11-01&tools=claude-code&group=week

Every resource below works there with the filters listed, and the live consoles on this page use it.

Conventions

  • Method: every endpoint is GET. Responses are JSON unless format=csv.
  • Auth: none. All data is public, in your public repo.
  • CORS: Access-Control-Allow-Origin: *, so you can call it from any browser page.
  • Freshness: machines sync hourly; GitHub Pages rebuilds within about a minute and caches up to 10 minutes; the query layer caches up to 5 minutes.
  • Tokens: tokens = input + output + reasoning + cacheRead + cacheWrite. input excludes cached input. responses counts model calls.
  • Dates: YYYY-MM-DD days in the collector's local time zone.
  • Every response echoes handle (your GitHub username) and the applied filters.

Filters (query layer)

Accepted by every resource on tokentracker.patrickbrown.dev/api/v1/users/<you>/…. On GitHub Pages, use the range folders instead.

ParamValuesDefault
rangeall, ytd, Nd (e.g. 30d, 365d), or a year like 2026all

toolsComma-separated tool ids, e.g. claude-code,codexall

Resources

Profile

GET /api/v1/users/{handle}

A summary: all-time and this-year totals, tools, model and machine counts, first and last active day, last sync, and links to every resource.

Usage

GET /api/v1/users/{handle}/usage

Token usage over time.

ParamValues
groupday (default), week (ISO, starts Monday), month, year, total
splittool or model: adds split: { key: tokens } to each row
fillfalse to omit empty days (daily series are continuous by default)

Returns { group, split, totals, rows: [{ period, tokens, input, output, reasoning, cacheRead, cacheWrite, responses, split? }] }.

Models

GET /api/v1/users/{handle}/models

One row per model and tool, sorted by tokens: { model, provider, name, tool, tokens, input, output, reasoning, cacheRead, cacheWrite, responses, share, firstUsed, lastUsed }. Cursor reports totals only, as cursor/all.

Tools

GET /api/v1/users/{handle}/tools

One row per tool: { tool, name, tokens, …, responses, share, models, firstUsed, lastUsed }.

Heatmap

GET /api/v1/users/{handle}/heatmap

A ready-to-render calendar grid. Colour levels are ranked among active days so one huge day doesn't wash out the rest.

ParamValues
rangeyear (default: this calendar year, padded to Dec 31), 365d, 90d, any Nd, or a year
levels2–10 colour steps including empty (default 5)
weekStartsun (default) or mon
toolsFilter to some tools

Returns { range, levels, weekStart, total, max, activeDays, months: [{ label, week }], weeks: [[{ date, tokens, level } | null × 7], …] }. Days after today have tokens: null; cells outside the range are null.

Stats

GET /api/v1/users/{handle}/stats

Totals plus activeDays, firstDay, lastDay, busiestDay, longestStreak, currentStreak, averagePerActiveDay, today, thisMonth, topTool and topModel (by responses).

Devices

GET /api/v1/users/{handle}/devices

One row per machine: { device, tools, lastSync, tokens, …, firstUsed, lastUsed }.

Errors and limits

Errors use HTTP status codes and one shape:

{ "error": { "code": "bad_range", "message": "range must be all, ytd, Nd (e.g. 30d) or a year (e.g. 2026)" } }
StatusCodes
400bad_range, bad_date, bad_group, bad_split, bad_tools, bad_models, bad_levels, csv_unsupported
400bad_owner (not a valid GitHub username)
404user_not_found (no tokentracker-data Pages yet), unknown_resource
502github_unavailable (GitHub Pages didn't answer)
405method_not_allowed

Responses are cached at the edge for 5 minutes; your repo's data updates within about an hour of use.

Recipe: a heatmap

const hm = await (await fetch(`${API}/users/you/heatmap?range=year`)).json();
grid.style.gridTemplateColumns = `repeat(${hm.weeks.length}, 1fr)`;
grid.innerHTML = hm.weeks.flat().map((d) =>
  d ? `<i class="lvl-${d.level}" title="${d.date}: ${d.tokens ?? ''}"></i>` : '<i class="out"></i>'
).join('');
// CSS: .grid { display: grid; grid-auto-flow: column; grid-template-rows: repeat(7, 1fr); gap: 3px }

Recipe: a monthly chart by tool

const { rows } = await (await fetch(`${API}/users/you/usage?range=ytd&group=month&split=tool`)).json();
// rows[i] = { period: "2026-07", tokens, split: { "claude-code": 812345678, cursor: 123456789 } }
// Stack split values per bar; height = tokens / max(tokens).

Recipe: a model leaderboard

const { rows } = await (await fetch(`${API}/users/you/models?range=30d`)).json();
rows.filter((m) => m.model !== 'cursor/all')
    .sort((a, b) => b.responses - a.responses)
    .slice(0, 5);

Privacy

Only daily token counts per tool and model leave your machine: never prompts, code, file paths or API keys. Run npx @bicrick/tokentracker sync --dry to see exactly what is saved. Each computer's files are named by a one-way hash of its hardware id, so setting up the same machine again never counts your usage twice. Your data is public in your repo, like the API.

Storage: your GitHub

tokentracker has no database. Everything lives in github.com/<you>/tokentracker-data, which you own:

tokentracker.json                  settings (Cursor handle)
machines/<machine-id>/<year>.json   daily totals, one file per computer per year
FORMAT.md                          the data format, so it stays readable forever
.github/workflows/tokentracker.yml builds your static API on GitHub Pages
  • History is never lost. Tools delete old logs (Claude Code after about 30 days); saved days stay in your repo. New syncs only add or update days.
  • Built to last. Files carry a format version and every release reads every format. The CLI keeps the workflow file up to date for you.
  • Stopped syncing? You get a desktop notification, and after 3 quiet days the repo's Action opens an issue (GitHub emails you). It closes itself when the machine is back.
  • Delete everything: delete the repo and run npx @bicrick/tokentracker uninstall.

CLI

Run each as npx @bicrick/tokentracker <command>. Nothing is installed globally.

initGuided setup
connectChoose tools, add custom folders, connect Cursor
sync [--dry]Save now; --dry prints exactly what is saved
statusRepo, machine, last upload, tools and recent syncs
install / uninstallBackground sync on or off
build / checkRun by your repo's Action: build the static API, flag quiet machines

Troubleshooting

SymptomFix
init printed a code and exited (status 2)Open github.com/login/device, enter the code, then run the same command again
API says user_not_foundYour repo's first build hasn't finished. Check github.com/<you>/tokentracker-data/actions; it takes about a minute
status says "No upload since…", or an issue "X stopped syncing" opened in your repoRun npx @bicrick/tokentracker@latest init --yes on that computer. The issue closes itself
"No scheduler on this machine"Minimal Linux and containers may lack cron and systemd: run npx @bicrick/tokentracker sync from your own scheduler
No Cursor datanpx @bicrick/tokentracker connect --cursor <cursor.com username>
A tool is missing or wrongnpx @bicrick/tokentracker connect, or connect --add <tool> <path>
Want to see exactly what's savednpx @bicrick/tokentracker sync --dry

Logs: ~/Library/Logs/tokentrack.log (macOS), ~/.local/state/tokentrack/sync.log (Linux), %LOCALAPPDATA%\tokentrack\sync.log (Windows).
