tokentracker

tokentracker saves the token usage your AI coding tools already record (daily totals per tool and model, on every machine) into a repo on your own GitHub, and publishes it as an API on GitHub Pages. There is no tokentracker account and no tokentracker database.

Your API lives at:

https://<your-github-username>.github.io/tokentracker-data/api/v1/

Quickstart

curl https://bicrick.github.io/tokentracker-data/api/v1/stats.json
const res = await fetch('https://bicrick.github.io/tokentracker-data/api/v1/30d/usage.json');
const { totals, rows } = await res.json();
// rows: [{ period: "2026-10-22", tokens, input, output, reasoning, cacheRead, cacheWrite, responses, split }, ...]

That's real data for bicrick. Swap in your GitHub username once you've installed it.

Install

Needs Node 22.13+ on macOS, Linux or Windows, and a GitHub account. Nothing else.

npx @bicrick/tokentracker init
  1. Finds the AI tools on this computer and shows what it found. You choose which to track.
  2. Asks for your Cursor username, if you use Cursor (optional).
  3. Signs you in to GitHub: open github.com/login/device and enter the code it shows. (If the gh CLI is signed in, it uses that instead.) The sign-in can only touch public repos and workflows, and doesn't expire.
  4. Creates a public tokentracker-data repo on your GitHub, saves your history there and turns on GitHub Pages.
  5. Turns on an hourly background sync (no admin rights).

Setup takes under a minute. Your repo's Action then builds your API in about a minute more. On another computer, run the same command with the same GitHub account; totals add up and the same computer is never counted twice.

With an agent

Ask: Install tokentracker for me. The agent asks whether you use Cursor, runs npx @bicrick/tokentracker@latest init --yes, shows you the GitHub sign-in code (init exits with status 2 while it waits), then runs the same command again to finish. Agents get everything from llms.txt.

The API

Your API is a set of JSON files on your GitHub Pages, rebuilt by your repo's Action about a minute after each sync:

https://<you>.github.io/tokentracker-data/api/v1/
  • Public: no key, plain GET, CORS *, so any page, script or agent can read it.
  • Fresh: machines sync hourly; GitHub caches files for up to 10 minutes.
  • Time ranges are folders: no folder means all time; ytd/, 30d/, 90d/ and 365d/ hold the same files for that range, e.g. 30d/usage-week.json.
  • Tokens: tokens = input + output + reasoning + cacheRead + cacheWrite; input excludes cached input; responses counts model calls. Dates are calendar days on the machine.
  • Every file includes handle (your GitHub username), generatedAt and filters (from and to show the range it covers).

Each file below has a live console: change the username or range and press Send.

stats.json

Totals plus activeDays, firstDay, lastDay, busiestDay, longestStreak, currentStreak, averagePerActiveDay, today, thisMonth, topTool, topModel (by responses) and short display strings like "9.83B".

usage.json · usage-week.json · usage-month.json

Usage over time by day, week (starting Monday) or month, split by tool. Daily rows include empty days.

{ group, split: "tool", totals, rows: [{ period, tokens, input, output, reasoning, cacheRead, cacheWrite, responses, split: { "claude-code": 123, … } }] }

models.json

One row per model and tool, sorted by tokens: { model, provider, name, tool, tokens, input, output, reasoning, cacheRead, cacheWrite, responses, share, firstUsed, lastUsed }. Cursor has totals only, as cursor/all.

tools.json

One row per tool: { tool, name, tokens, …, responses, share, models, firstUsed, lastUsed }.

heatmap.json · heatmap-365d.json · heatmap-90d.json

A ready-to-render calendar grid for this calendar year, the last 365 days or the last 90. Levels 0–4 are ranked among active days, so one huge day doesn't wash out the rest.

{ range, levels, weekStart, total, max, activeDays, months: [{ label, week }], weeks: [[{ date, tokens, level } | null × 7], …] }

Days after today have tokens: null; cells outside the range are null.

profile.json

A one-file summary of your data (not an account; there are none): all-time and this-year totals, tools, model and machine counts, first and last day, last sync, and links to every other file.

rows.json and index.json

rows.json has every daily row ({ date, source, model, input, output, reasoning, cache_read, cache_write, messages, device }, where device is an anonymous label like "Computer 1") for your own queries. index.json lists every file.

Errors

A file that doesn't exist returns GitHub's 404 page. Usually that means the username is wrong, or the repo's first build hasn't finished (check github.com/<you>/tokentracker-data/actions).

Recipe: a heatmap

const API = 'https://you.github.io/tokentracker-data/api/v1';
const hm = await (await fetch(`${API}/heatmap.json`)).json();
grid.style.gridTemplateColumns = `repeat(${hm.weeks.length}, 1fr)`;
grid.innerHTML = hm.weeks.flat().map((d) =>
  d ? `<i class="lvl-${d.level}" title="${d.date}: ${d.tokens ?? ''}"></i>` : '<i class="out"></i>'
).join('');
// CSS: .grid { display: grid; grid-auto-flow: column; grid-template-rows: repeat(7, 1fr); gap: 3px }

const { rows } = await (await fetch(`${API}/ytd/usage-month.json`)).json();
// rows[i] = { period: "2026-07", tokens, split: { "claude-code": 812345678, cursor: 123456789 } }
// Stack split values per bar; height = tokens / max(tokens).

Recipe: a model leaderboard

const { rows } = await (await fetch(`${API}/30d/models.json`)).json();
rows.filter((m) => m.model !== 'cursor/all')
    .sort((a, b) => b.responses - a.responses)
    .slice(0, 5);

Privacy

Only daily token counts per tool and model leave your machine: never prompts, code, file paths, API keys or your computer's name. Computers show up only as "Computer 1", "Computer 2" and so on. Run npx @bicrick/tokentracker sync --dry to see exactly what is saved. Each computer's files are named by a one-way hash of its hardware id, so setting up the same machine again never counts your usage twice. Your data is public in your repo, like the API.

Storage: your GitHub

tokentracker has no database. Everything lives in github.com/<you>/tokentracker-data, which you own:

tokentracker.json                  settings (Cursor handle)
machines/<machine-id>/<year>.json   daily totals, one file per computer per year
FORMAT.md                          the data format, so it stays readable forever
.github/workflows/tokentracker.yml builds your static API on GitHub Pages
  • History is never lost. Tools delete old logs (Claude Code after about 30 days); saved days stay in your repo. New syncs only add or update days.
  • Built to last. Files carry a format version and every release reads every format. The CLI keeps the workflow file up to date for you.
  • Stopped syncing? You get a desktop notification, and after 3 quiet days the repo's Action opens an issue (GitHub emails you). It closes itself when the machine is back.
  • Delete everything: delete the repo and run npx @bicrick/tokentracker uninstall.

CLI

Run each as npx @bicrick/tokentracker <command>. Nothing is installed globally.

initGuided setup
connectChoose tools, add custom folders, connect Cursor
sync [--dry]Save now; --dry prints exactly what is saved
statusRepo, machine, last upload, tools and recent syncs
install / uninstallBackground sync on or off
build / checkRun by your repo's Action: build the static API, flag quiet machines

Troubleshooting

SymptomFix
init printed a code and exited (status 2)Open github.com/login/device, enter the code, then run the same command again
A file returns 404Your repo's first build hasn't finished. Check github.com/<you>/tokentracker-data/actions; it takes about a minute
status says "No upload since…", or an issue "X stopped syncing" opened in your repoRun npx @bicrick/tokentracker@latest init --yes on that computer. The issue closes itself
"No scheduler on this machine"Minimal Linux and containers may lack cron and systemd: run npx @bicrick/tokentracker sync from your own scheduler
No Cursor datanpx @bicrick/tokentracker connect --cursor <cursor.com username>

Want to see exactly what's savednpx @bicrick/tokentracker sync --dry

Logs: ~/Library/Logs/tokentrack.log (macOS), ~/.local/state/tokentrack/sync.log (Linux), %LOCALAPPDATA%\tokentrack\sync.log (Windows).

Custom queries (optional)

The files cover the common ranges. For anything else (exact dates, one tool or model, other groupings, CSV), tokentracker.patrickbrown.dev can compute it from your rows.json on request. It stores nothing:

https://tokentracker.patrickbrown.dev/api/v1/users/<you>/usage?from=2026-11-01&tools=claude-code&group=week

Resources: usage, models, tools, heatmap, stats. Filters: range, from, to, tools, models, group, split, fill=false, format=csv. Full spec: openapi.json.
