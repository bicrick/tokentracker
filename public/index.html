how it works

      
    
        
  • 1. run init
    It finds your local usage and shows you what it found before anything is sent.
    • 
        
  • 2. choose storage
    A free account on tokentracker cloud, or your own server. Self-hosting is one Vercel deploy.
    • 
        
  • 3. that's it
    A background job syncs every hour with no admin rights or permission prompts. Run init on each computer and the totals add up. Change tools any time with tokentrack connect.
    • 
      

    


    

      
sources

      
    
        
  • claude code
    Read from ~/.claude/projects.
    • 
        
  • codex
    CLI, IDE extension and app. Read from ~/.codex/sessions.
    • 
        
  • opencode
    Including GitHub Copilot and any provider. Read from ~/.local/share/opencode.
    • 
        
  • gemini cli
    Read from ~/.gemini/tmp.
    • 
        
  • copilot cli
    Read from ~/.copilot/session-state.
    • 
        
  • cline · roo · kilo
    In VS Code, Cursor, Windsurf and VSCodium. Read from each editor's extension storage.
    • 
        
  • cursor
    Pulled from your public cursor.com/@handle profile.
    • 
      

    


    

      
privacy

      

        Uploads contain only a date, tool, model and token counts. The server rejects anything else.
        Run tokentrack sync --dry to see the exact payload:
      

      
{ "date": "2026-11-17", "source": "opencode", "model": "github-copilot/claude-opus-5.5",
  "input": 381, "output": 138, "cacheRead": 8448, "messages": 1 }

      
Keys are stored hashed. tokentrack delete-account removes everything.

    


    

      
put it on your site

      
fetch('https://tokentracker-nu.vercel.app/api/activity?handle=you')

      
Returns daily totals per tool in the same shape as GitHub-style heatmaps.
